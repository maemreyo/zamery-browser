# Community support

Use the project surfaces according to the kind of help you need:

- **GitHub Discussions** — usage questions, setup help, integration ideas, design exploration, and community Q&A.
- **GitHub Issues** — reproducible bugs and actionable feature requests. Use the provided issue forms so maintainers have the versions and reproduction context needed to triage the report.
- **GitHub Pull Requests** — focused code, documentation, tests, or examples that are ready for review. See [CONTRIBUTING.md](CONTRIBUTING.md).
- **GitHub private vulnerability reporting** — suspected security vulnerabilities. Follow [SECURITY.md](SECURITY.md); do not disclose vulnerabilities in a public issue or discussion.

When asking for technical help, include the relevant `@zamery/*` package versions, Node.js version, Firefox/provider version when applicable, and the smallest safe reproduction. Remove credentials, cookies, tokens, private page content, and other secrets from logs or screenshots before posting them publicly.

Community support is best effort. A discussion or issue is not a guarantee of a response time, roadmap commitment, or compatibility outside the supported scope documented in the repository.
